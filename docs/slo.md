# Service-level objectives

These are targets, not claims of achieved reliability. Measured evaluation, load, and chaos results are generated by project commands and linked from the README only after they exist.

## SLO 1 — analysis success

At least **99.5%** of valid `POST /api/v1/incidents/analyse` requests succeed over a rolling calendar month. Client-caused 4xx responses, including schema validation and rate limiting, are excluded from the denominator. Server errors, exhausted provider paths, and persistence failures count as failures.

## SLO 2 — analysis latency

- Mock mode p95 is below **3 seconds**.
- Live LLM mode p95 is below **12 seconds**.

The modes are labelled and reported separately. Cached responses are also labelled so they cannot conceal provider latency.

## SLO 3 — fallback availability

When the primary provider fails, at least **95%** of otherwise valid analysis requests receive a successfully validated rule-based fallback response. A fallback is always marked `fallback_used=true` and `requires_human_escalation=true`.

## Measurement

Prometheus counters and histograms provide the production-style indicators. Deterministic evaluation, Locust, and the chaos demonstration provide reproducible local evidence; they do not establish a monthly uptime record.
